# ความจำ

[English](../memory.md) | ไทย

bot จำสิ่งสำคัญข้ามบทสนทนา และคุณอ่าน ดาวน์โหลด หรือลบทุกอย่างที่ bot เก็บไว้ได้

## สิ่งที่ bot จำ

bot เขียนโน้ตระหว่างทำงาน: ความชอบของคุณ ข้อเท็จจริงเกี่ยวกับงาน และสิ่งที่ลองทำไปแล้ว โน้ตถูกจัดทำดัชนีไว้ในไฟล์ชื่อ
`MEMORY.md`

คุณบอก bot ตรง ๆ ก็ได้: "จำไว้ว่าใบแจ้งหนี้ไปที่โฟลเดอร์การเงิน"

bot เขียนโน้ตสั้น ๆ หนึ่งข้อเท็จจริงต่อบรรทัด เมื่อบางอย่างเปลี่ยน bot จะเขียนโน้ตเดิมใหม่แทนการเพิ่มโน้ตที่สอง
และลบโน้ตที่ไม่จริงแล้ว bot เก็บโน้ตใน `MEMORY.md` ได้สูงสุด 4 KB โดยรวมหรือลบโน้ตเพื่อให้มีที่ว่าง
คุณยังเพิ่มเองได้อีก

หากต้องการดูว่า bot จำอะไรไว้ คลิกชื่อ bot ที่ด้านบนแชทแล้วเปิด **ความจำ (Memory)** โน้ตแต่ละรายการแก้ไข ดาวน์โหลด
หรือลบได้ ในแอปมือถือ โน้ตอยู่ในการตั้งค่าแชทของ bot ซึ่งแก้ไขหรือลบได้

## ความจำร่วม

บางอย่างที่ทุก bot ควรรู้ เช่น ชื่อของคุณ บริษัท หรือรูปแบบรายงานที่คุณชอบ ให้ใส่ไว้ใน **Shared memory**:
ทุก bot ใน [space](../spaces.md) อ่านโน้ตเหล่านี้และช่วยอัปเดตให้เป็นปัจจุบัน

อยู่ใน **ตั้งค่า (Settings) → Memory** บนเว็บ เดสก์ท็อป และมือถือ

## Memory provider

คุณเชื่อมบริการความจำเพิ่มได้ เพื่อให้ bot เรียกคืนข้อเท็จจริงตามความหมายได้ด้วย ไม่ใช่แค่อ่านโน้ต
ใน **ตั้งค่า (Settings) → Memory** เลือก **Connect memory provider**:

- **Supermemory**: บริการคลาวด์ของ Supermemory หรือ instance ของคุณเอง bot ลืมความจำตาม id ได้
  แต่เฉพาะความจำที่ bot เรียกคืนได้: ของตัวเอง หรือความจำร่วมของ Space เมื่อใช้ขอบเขต Shared
- **Serenity**: เลือก **Recall and write** หรือ **Recall only** เพื่อให้เป็นแบบอ่านอย่างเดียว
- **Honcho**: บันทึกและเรียกคืนข้อเท็จจริงโดยใช้ peer ของ Rakazo เอง ใส่ workspace และ **User peer**
  เพิ่มได้ถ้าต้องการเรียกคืนสิ่งที่ Honcho รู้เกี่ยวกับคุณอยู่แล้วด้วย peer เดิมนั้นยังเป็นแบบอ่านอย่างเดียว
  Rakazo เขียนข้อเท็จจริงใหม่ลง peer ของตัวเองใน workspace เดียวกัน
- **Hindsight**: บริการคลาวด์ของ Hindsight หรือเซิร์ฟเวอร์ของคุณเอง แต่ละ bot มีความจำของตัวเอง เมื่อใช้ขอบเขต
  Shared bot ยังใช้ความจำร่วมหนึ่งชุดสำหรับ Space รวมถึงรอบสนทนาในแชทตรงที่เรียนรู้มาด้วย
  bot เรียนรู้จากบทสนทนา (แชทของตัวเอง แชทกลุ่ม และข้อความระหว่าง bot) เว้นแต่คุณจะปิด
  **Learn from conversations** การเรียนรู้ใช้ข้อความบางส่วนในขอบเขตจำกัดจากข้อความล่าสุดของคนและคำตอบ
  ทั้งในแชทตรงและแชทกลุ่ม การบันทึกและการส่งบทสนทนาใช้งบเวลาสามสิบวินาทีร่วมกัน
  ครอบคลุม DNS และ bank ทั้งสอง การส่งที่ล้มเหลวจะลองใหม่ด้วย operation ID ที่คงที่ ขณะที่การล้างข้อมูล
  ยังทำงานอยู่สำหรับการเขียนที่ถูกรับไปบางส่วน การล้างข้อมูลแต่ละครั้งมีกำหนดเวลาสิบวินาที และลบเอกสารรายรอบ
  เป็นชุดคู่ขนานที่มีขนาดจำกัด การล้างข้อมูลที่ล้มเหลวจะลองใหม่ได้สูงสุดสิบสองครั้งผ่านคิวที่มีอยู่
  โดยใช้ตัวตนการเชื่อมต่อที่บันทึกไว้ การล้างข้อมูลยังเป็นแบบพยายามให้ดีที่สุด หากการเผยแพร่ล้มเหลว
  หรือโปรเซสหยุดก่อนที่การลองใหม่จะเข้าคิว หากโหลดการเชื่อมต่อที่ตั้งค่าไว้ไม่ได้
  การล้างข้อมูลก็บันทึกตัวตนสำหรับลองใหม่อย่างปลอดภัยไม่ได้เช่นกัน ระบบล่มหรือการเขียนที่ค้างเกินช่วงเวลา polling
  อาจทำให้ความจำขาดหายหรือล้าสมัย หากคำตอบของการส่งไม่แน่นอน การตรวจของการล้างข้อมูล
  จะดำเนินต่อตลอดช่วงเวลาที่จำกัด บทสนทนาที่ไม่เปลี่ยนต้องการเพียงการตรวจ generation ในเครื่อง
  โดยไม่ต้องดึงข้อมูลรับรอง การปฏิเสธภายหลังพิสูจน์ไม่ได้ว่าความพยายามก่อนหน้าไม่ได้บันทึกอะไรไว้
  การตัดการเชื่อมต่อหรือเปลี่ยนการเชื่อมต่อจะหยุดการล้างข้อมูลบนบริการเดิม แต่ไม่ลบข้อมูลที่นั่น ที่นี่ bot
  ลืมความจำทีละรายการไม่ได้ การลบ bot พร้อมความจำจะลบเซสชันบทสนทนาที่ bot นั้นเก็บไว้
  รวมถึงกลุ่มที่ bot ออกไปแล้ว สำเนาที่ bot อื่นเรียนรู้ไว้เองยังคงอยู่
  หากต้องการให้ bot อ่านความจำที่แอปอื่นเก็บไว้ใน Hindsight เดียวกัน ให้ระบุ bank ของแอปนั้น
  ใต้ **Recall from banks** bot อ่าน bank เหล่านั้นผ่านการเรียกคืนแบบระบุชัดเท่านั้น ไม่ใช่บริบทอัตโนมัติ และไม่เขียนลงไป ชื่อที่ขึ้นต้นด้วย
  `rakazo-` สงวนไว้สำหรับแยก Space และนำเข้าไม่ได้ bot ยังขอให้ความจำของ bot ตัวเอง
  ตอบคำถามโดยรวมสิ่งที่รู้ได้ด้วย การ reflection ไม่ query
  bank ร่วมของ Space ข้อเท็จจริงที่แชร์ยังเรียกคืนได้ผ่าน recall สรุปของแชทยาวอยู่ใน
  Rakazo: Hindsight เรียนรู้จากบทสนทนาเอง ไม่ใช่จากสรุป
- **Mnemoverse**: บริการคลาวด์เท่านั้น ใส่ API key Rakazo บันทึกข้อเท็จจริงที่ระบุชัดไว้ใน
  domain ต่อ bot เมื่อใช้ขอบเขต Shared ข้อเท็จจริงจะถูกบันทึกลง domain เดียวสำหรับ Space แทน ซึ่ง
  bot เรียกคืนพร้อมกับของตัวเอง bot ที่เป็น Isolated จะไม่เห็น bot ลืมความจำตาม id ได้
  แต่เฉพาะใน domain ที่ bot เรียกคืนได้ ไม่ใช่ส่วนอื่นของบัญชี Mnemoverse ของคุณ ข้อเท็จจริงที่ยาวเกิน 10,000 ตัวอักษรจะไม่ถูกบันทึก
  สรุปของแชทยาวอยู่ใน Rakazo

หากต้องการเปลี่ยนการตั้งค่าของ provider ที่เชื่อมไว้ เลือก **Edit** ต้องใส่ key ใหม่
เฉพาะเมื่อเปลี่ยนที่เชื่อมต่อหรือสิ่งที่อ่านได้

เมื่อเชื่อมแล้ว **Default scope** กำหนดว่า bot แชร์อะไรใน provider:

- **Isolated**: แต่ละ bot เรียกคืนเฉพาะสิ่งที่ตัวเองบันทึก นี่คือค่าเริ่มต้น
- **Shared**: bot ใน space เรียกคืนจากชุดเดียวกัน

การตั้งค่าของแต่ละ bot จะมี **Memory scope** ใต้ **ขั้นสูง (Advanced)** ด้วย เพื่อให้ bot ตัวหนึ่งต่างจาก
ค่าเริ่มต้นได้

### ที่มาของความรู้ (เวอร์ชัน 1)

การเรียนรู้กับอำนาจในการสั่งงานแยกจากกัน bot เรียนรู้จากคน bot อื่น และคำตอบที่มาจากเนื้อหาภายนอก
ในบทสนทนาที่ตัวเองเข้าถึงได้ ความรู้นั้นอยู่ในความจำส่วนตัวหรือความจำที่ตั้งใจแชร์ของ Space ที่รับ
การเรียนรู้ไม่ให้สิทธิ์เข้าถึง Space อื่น

นโยบายแหล่งที่มาตั้งใจให้ระมัดระวัง:

- ทุกข้อความของ bot คำตอบเก่า สรุป และความจำที่เรียกคืน เป็นข้อมูลที่ได้มาต่อ การนำกลับมาใช้ไม่เคย
  รับรองว่าแหล่งที่มาสะอาด หรือทำให้กลายเป็นคำสั่งของเจ้าของ
- การเรียนรู้จากบทสนทนาเก็บชื่อผู้พูดไว้ และ recall เก็บการระบุแหล่งที่มาของ provider เมื่อมี
  สิ่งเหล่านี้ระบุแหล่งที่มา แต่ไม่ให้อำนาจหรือรับรองความถูกต้องของข้อเท็จจริง
- semantic recall และ reflection ยังเป็นข้อมูลที่ได้มาต่อ แม้ bank จะเป็นของ bot ตัวเดียวกัน หรือ
  provider ไม่ใส่การระบุ bank ภายนอกซึ่งเป็นตัวเลือก
- recall อัตโนมัติรวมเฉพาะ bank ของ bot และ bank ของ Space ที่ตั้งใจแชร์ bank ที่นำเข้าต้องใช้ recall แบบระบุชัดและการป้องกันการกระทำสำหรับข้อมูลใหม่
- ประวัติที่เก็บไว้และ recall อัตโนมัติไม่เปลี่ยนสิทธิ์ปัจจุบันของเจ้าของ ข้อมูลใหม่จากภายนอก
  รวมถึง semantic recall และ reflection แบบระบุชัด ยังคงการป้องกันการกระทำที่มีอยู่

ไม่มี flag ว่าสะอาดต่อรอบ หรือกราฟสายที่มา วิธีนี้เลี่ยงทั้งการอ้างว่าคำตอบเก่ายืนยัน
แหล่งที่มาที่สะอาดได้ และการทำให้งานปกติต้องรอการบันทึกที่มา การเรียนรู้ข้าม bot
ยังเปิดอยู่ และการแชร์ความรู้ไม่เคยข้ามการตรวจสิทธิ์ของ Space ที่รับ

## งานค้าง

แยกจากความจำ แต่ละ bot เก็บรายการสั้น ๆ ชื่อ **Open work**: สิ่งที่เริ่มแล้วแต่ยังไม่เสร็จ
อยู่ในการตั้งค่าของ bot คุณเพิ่มรายการให้ หรือทำเครื่องหมายว่าเสร็จได้

เมื่อเปิดการเช็กอินรายวัน รายการที่ไม่มีใครแตะต้องเป็นเวลา 14 วันจะถูกพักไว้โดยอัตโนมัติ รายการที่พักไว้
อยู่หลัง **Show more** ซึ่งคุณเปิดใหม่ได้ และ bot ยังอ่านได้

## ความจำข้าม space

ความจำไม่ข้าม [space](../spaces.md) bot ใน space หนึ่งอ่านโน้ตจากอีก space ไม่ได้
