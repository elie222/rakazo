# Routines

[English](../routines.md) | ไทย

routine คือ prompt ที่ bot รันเอง: ตามตารางเวลา เมื่อมีบางอย่างเปลี่ยน หรือเมื่อบริการอื่นเรียก

## ขอในแชท

วิธีที่เร็วที่สุดคือขอ:

- "ทุกวันทำการ 8 โมงเช้า สรุปกล่องจดหมายของฉัน"
- "อีก 20 นาทีเตือนให้โทรหา Dana"
- "ทุกวันจันทร์ ตรวจหน้าราคาของคู่แข่งแล้วบอกว่ามีอะไรเปลี่ยน"

bot จะสร้าง routine และรายงานผลแต่ละรอบกลับในแชทเดิม

## สร้างหรือแก้ไขเอง

บนเว็บหรือเดสก์ท็อป คลิกชื่อ bot ที่ด้านบนแชทเพื่อเปิดแผงของ bot ใน **Routines** เลือก **New routine**
ถ้ายังไม่มีรายการ หรือ **+** (ป้าย **Create routine**) ถ้ามี routine อยู่แล้ว หากต้องการแก้ไข ให้เลือก routine จากรายการ

1. ตั้ง **Name** ของ routine และเขียน **Instruction**: สิ่งที่ต้องทำทุกครั้งที่รัน
2. ใต้ **When to run** เลือก **Add trigger**
3. เลือก **Save**

ใต้ **ขั้นสูง (Advanced)** คุณกำหนด **Model** และระดับ **Thinking** ของ routine เองได้ เช่น
โมเดลที่ถูกกว่าสำหรับการตรวจรายวันแบบง่าย

## ทริกเกอร์

### ตามตารางเวลา

ทุกชั่วโมง ทุกวัน วันทำการ ทุกสัปดาห์ ทุกเดือน หรือช่วงเวลาที่กำหนดเอง **Advanced...**
รับ cron expression เวลาใช้เขตเวลาของคุณ ซึ่งตั้งใน **ตั้งค่า (Settings) → General**

### เมื่อมีบางอย่างเปลี่ยน

bot ตรวจบางอย่างตามช่วงเวลาที่ตั้ง (**Check every** ตั้งแต่ 5 นาทีถึงหนึ่งวัน) และรันเฉพาะเมื่อมีการเปลี่ยน
**What to watch** เป็นไฟล์หรือโฟลเดอร์บนคอมพิวเตอร์ ผลลัพธ์ของคำสั่ง หรือเครื่องมือจากแอปที่เชื่อมไว้ก็ได้
อาร์กิวเมนต์ของเครื่องมือใส่วันที่ที่เลื่อนตามปฏิทินได้: ขอให้ bot เฝ้าดู เช่น สิ่งที่ครบกำหนดก่อน `{{today+2d}}`
เปิด **Post "No changes" in chat** ถ้าต้องการข้อความแจ้งทุกครั้ง การเฝ้าดูใช้ร่วมกับตารางเวลาไม่ได้

### Webhook

ให้ URL และ key บริการใดก็ตามที่ส่ง POST request ได้จะเริ่ม routine ได้

### Git event

ให้ URL สำหรับเพิ่มเป็น GitHub webhook เพื่อให้ push, issue และ pull request เริ่ม routine ได้

### อีเมล

รันเมื่อมีเมลเข้าที่อยู่ของ bot เอง เช่น `scout@bots.example.com` ครั้งแรกให้เลือกส่วนหน้า @
ซึ่งจะเป็นของ bot ตลอดไป ส่งต่อหรือ CC เมลไปที่อยู่นั้น ด้วยมือหรือด้วยกฎของกล่องจดหมาย แล้ว routine จะรันพร้อมอีเมลนั้น
กฎต้องเป็นการส่งต่อ (forward) ไม่ใช่การเปลี่ยนเส้นทาง (redirect): เมลที่เปลี่ยนเส้นทางยังคงผู้ส่งและผู้รับเดิม
จึงไม่ระบุถึง bot เลือกว่าใครเริ่มได้: **Only me** หรือ **Anyone at** โดเมนอีเมลของคุณ
เมลจากคนอื่นและเมลที่ส่งแบบ BCC ไม่เริ่มอะไร แต่ bot ยังเก็บทุกอีเมลไว้ในกล่องจดหมายของตัวเองเสมอ
ถ้าตรวจสอบเมลจากที่อยู่ของคุณเองไม่ได้ แชทจะแจ้ง ซึ่งผู้ให้บริการอีเมลของคุณต้องเปิด DKIM signing สำหรับโดเมนของคุณ
แสดงเฉพาะเมื่อเซิร์ฟเวอร์ของคุณ[รับอีเมล](../self-host-inbound-email.md)ได้

### ข้อความ Slack

รันเมื่อ bot ได้รับข้อความใน Slack ต้อง[เชื่อม Slack](../messaging-apps.md)ก่อน

> [!NOTE]
> รอบของ routine ที่เริ่มจาก webhook อีเมล หรือข้อความ Slack ทำตามโหมด[การอนุมัติ](./approvals.md)
> และรายการ Always allow ของคุณ เนื่องจากข้อความภายนอกอาจชี้นำได้ เครื่องมือที่เปลี่ยนแปลงบางอย่าง
> จะถูกตรวจแม้จะไม่เคยถามในแชทของคุณเอง อาจไม่มีใครเฝ้าดู การ์ดอนุมัติที่โพสต์จึงหมดอายุหลัง 30 นาที
> โดยค่าเริ่มต้นและการกระทำนั้นจะไม่ถูกทำ `UNATTENDED_APPROVAL_EXPIRE_AFTER_MS` เปลี่ยนช่วงเวลานี้
> การตั้ง Always allow ให้เครื่องมืออย่าง shell หรือเบราว์เซอร์จะทำให้ข้อความภายนอกใช้เครื่องมือนั้นได้อย่างอิสระ

## ทดสอบ หยุดชั่วคราว และดูผล

- **Test run** รัน routine ที่บันทึกไว้ทันที
- ปิด **Active** เพื่อหยุด routine ชั่วคราวโดยไม่ลบ
- **Run history** แสดงทุกรอบที่ผ่านมาและผลลัพธ์
- routine ที่กำลังรันแสดง **Running** ในรายการ พร้อม **Stop**

## บนมือถือ

แอปมือถือแสดง routine ของ bot จากโปรไฟล์ แตะ **+** เพื่อสร้างใหม่ แตะ routine เพื่อดู instruction
ตารางเวลา รอบถัดไป และประวัติการรัน พร้อมสวิตช์หยุดชั่วคราวและปุ่มทดสอบ **Edit routine** เปลี่ยนชื่อ
instruction และตารางเวลา หรือลบ routine ทริกเกอร์ Webhook, Git event, ข้อความ Slack และการเปลี่ยนแปลง
รวมถึงโมเดลเฉพาะของ routine ตั้งค่าในแชทหรือในแอปเว็บหรือเดสก์ท็อป มือถือแสดงและคงไว้ตามเดิม
