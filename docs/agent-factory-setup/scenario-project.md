# 场景：团队开发一个项目（完整走法）

> 以一个真实小需求为例：给「内部项目管理系统」新增「需求导出 CSV」功能。
> 展示 7 个角色如何接力，以及人类在哪里介入。

## 一、一次性准备（项目启动）

1. **建 Space 作为项目边界**：例如 `内部系统`（隔离数据/权限/技能）。
2. **建 Board**：就是项目的需求池；列映射见 `board.md`。
3. **建群聊**：把 7 个 bot 拉进同一群聊（协作现场）。
4. **接真实仓库与 CI**：GitHub 集成给 `dev`/`reviewer`/`qa`；CI（GitHub Actions）跑测试；`ops` 配置部署目标与凭证（Vault 类机制）。
5. **启用 6 条 routine**（导入后默认暂停）。

## 二、单个需求的完整时间线

### 录入与确认（Day 0）

1. 任何人（或 bot）在 Board 建票：「需求导出 CSV」，描述见票模板。
2. **pm（每 6h）** 扫板 → 标 `high` + 理由「客户反馈高频」；价值明确，跳过门禁 0。
3. **po（每 15min）** 扫板 → 产出规格贴票：目标、范围、**不做**（不做 Excel 格式）、DoD、约束（复用现有导出模块）。
4. **门禁 1**：po 发「规格批准」卡 → **人类批准**。
5. **coordinator（每 5min）** 扫板 → 见规格已批准 → 指派 `dev`、移 `doing`、群聊 @dev 开工。

### 开发与评审（Day 1）

6. **dev** 被唤醒 → 沙箱 clone 仓库 → 按规格实现（一次一张票）→ 补测试 → 本地全绿 → 提 PR（描述带票号 `Board-12`）→ 票评论「实现完成 + PR 链接」→ 票移 `review` → @reviewer。
7. **reviewer**（git event routine 被 PR 唤醒）→ 审 diff → 发现日期格式硬编码 → PR 评论列 issue → @dev 返工，票保持 `review`。
8. **dev** 修复 → reviewer 复核通过、CI 绿 → 票评论「评审通过」→ @qa。
9. **qa** 验收 → 沙箱检出分支跑完整测试 + 冒烟 + 实测导出 → 验收报告绿灯 → 票移 `done` → @ops 并请求「上线批准」。
10. **门禁 2**：**人类批准上线**。

### 部署与收尾（Day 1 下午）

11. **ops**（每 30min 巡检 `done` 列，或被 @）→ 确认绿灯 + 批准卡 → 按 `deploy-sop` 发布 → 健康检查 → 部署日志贴票 → 变更说明按模板产出 → 票移 `closed` → 群聊宣布完成。

## 三、并行与多项目

- **多张票并行**：Board 同时多票；`dev` 一次只做一张（SOP 约束），`reviewer`/`qa`/`coordinator` 可并行处理多张；`pm` 负责排序避免 dev 被多张票抢。
- **多项目**：每个项目一个 Space（一套 Board + 群聊 + 团队副本）。团队配置可复制；项目间数据/权限隔离。
- **一个人管多个项目**：审批卡都会汇总到你的会话/通知，按门禁批准即可。

## 四、异常与升级（门禁 3）

- 任何角色 15 分钟无进展 → 转 `blocked` 并写卡点。
- `coordinator` 超时检测（doing 2h / review 4h / done 2h 无动静）→ @责任人追问 → 仍无回应 → 转 `blocked` + **群聊 @人类**。
- 人类在票上给结论（继续/换人/取消）→ `coordinator` 执行，票离开 `blocked`。

## 五、人在全程的介入点（总结）

| 时刻                     | 人类动作  |
| ------------------------ | --------- |
| 门禁 1：规格批准         | 批准/驳回 |
| 门禁 2：上线批准         | 批准/驳回 |
| 门禁 3：异常决策         | 给结论    |
| 门禁 0（可选）：需求确认 | 做/不做   |

其余全部自动。全程可追踪：票评论链上有规格、PR、评审、验收、部署证据；路线图由 `pm` 维护；交付看板由 Board + Page 呈现。

## 六、跑起来之后怎么调

- 卡在某个角色 → 先查它的 routine 是否启用、指令是否完整（见 `verification.md` 速查表）。
- 角色抢活/漏活 → 调整 `coordinator` 推进表或对应角色的「边界」段落。
- 流程不符合业务 → 改 SOP 段落，不必动代码；多次跑不顺再考虑二开硬编排。
