# Board 映射与票模板

Rakazo Board 是固定 6 列（contracts 写死）：`todo / doing / review / blocked / done / closed`。业务阶段映射如下，不改代码。

## 列映射

| Board 列  | 业务含义               | 谁推进                | 推进条件            |
| --------- | ---------------------- | --------------------- | ------------------- |
| `todo`    | 待处理（新需求已录入） | `po` 扫板例行 routine | 票有完整描述        |
| `doing`   | 开发中                 | `po` 指派 `dev`       | 规格批准卡已通过    |
| `review`  | 评审/验收中            | `reviewer`/`qa`       | PR 提出 / CI 完成   |
| `blocked` | 阻塞，等人决策         | 任一员工              | 需要门禁 3          |
| `done`    | 验收通过、待部署       | `qa`                  | 验收报告绿灯        |
| `closed`  | 完成（或取消）         | `ops`                 | 部署完成 / 决策取消 |

> `done` 语义是「finished-but-open」：验收过、但还没部署收尾，正好做待部署位。

## 票模板（新建票的描述）

```text
## 需求
一句话说明要解决什么问题。

## 背景
为什么现在做、影响谁。

## 验收标准（DoD）
- [ ] 可运行、有测试
- [ ] PR 评审通过、CI 绿
- [ ] 验收报告绿灯
- [ ] 部署完成、变更说明已回写

## 约束
仓库、环境、边界、不允许做的事。
```

## 优先级

| 优先级   | 含义     | 处理顺序 |
| -------- | -------- | -------- |
| `urgent` | 阻塞线上 | 立即     |
| `high`   | 本轮迭代 | 优先     |
| `normal` | 默认     | 常规     |
| `low`    | 排期外   | 最后     |

## 流转规则（写进 bot instructions 的公共约定）

1. 所有阶段变更必须留 comment：结论、证据链接（PR/报告/部署日志）、下一步责任人。
2. 指派 = 开工信号；员工只处理「指派给自己」的票，除非被 `@mention`。
3. 卡住 15 分钟无进展 → 转 `blocked` 并说明卡点与需要的决策。
4. 每张票的 DoD 全部勾选前，不得进入 `done`；部署未完成前，不得进入 `closed`。
5. 人可随时在票上评论介入；评论即最高优先级指令。

## 调度：谁是流程所有者

- **`coordinator` 是唯一调度入口**：指派、移列、停滞升级由它统一执行；其他角色只负责把「结果/证据」写到票上并在群聊 @ 下一个角色，不自行指派。
- 推进表与超时阈值见 `bots/coordinator.md`；`coordinator` 每 5 分钟扫板一次。
- 任何角色发现异常可先转 `blocked` 并 @人类，`coordinator` 负责跟进到结论。

## 产品管理：pm 与 po 的分工

- `pm`：backlog 优先级、路线图、需求理解冲突的仲裁；价值不明的票先向人类确认（门禁 0）。
- `po`：单张票的规格化、DoD、澄清与规格批准请求。
- 谁都不碰对方的产出：`pm` 不写规格，`po` 不改优先级。
