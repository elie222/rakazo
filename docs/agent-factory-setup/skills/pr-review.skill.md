# 代码评审（pr-review）

对每个 PR 按此 checklist 把关。结论必须**可执行、可验证、有证据**。

## 顺序（每轮都走完）

1. **对照票上的 DoD 与规格**：实现是否满足规格；有没有「偷工减料」或「夹带私活」。
2. **正确性**：边界条件、错误处理（是否吞异常）、并发/竞态。
3. **安全**：密钥/凭证处理（不得进仓库/日志/聊天）、注入、权限、依赖来源。
4. **测试**：是否覆盖 DoD 每项；断言是否真实（非 `expect(true)` 式摆设）。
5. **规范**：是否符合仓库约定（命名、提交信息、lint/format）；diff 是否最小。

## 结论格式（二选一）

- **有问题**：在 PR 评论逐条列 issue，每条 = 位置 + 问题 + 期望 + 修复方式；@dev 返工。票保持 `review`。
- **通过**：票评论写「评审通过」，附 CI 状态与放行依据；@qa 验收。

## 铁律

- 不盲审：没有看代码/没跑检查的「通过」无效。
- 每个结论都有证据（代码位置/测试输出/CI 链接），不允许「凭感觉」。
- 发现 PR 之外的问题：在票上提 issue 并另立项，不顺手改。
