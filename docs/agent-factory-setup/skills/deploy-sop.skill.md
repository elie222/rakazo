# 部署（deploy-sop）

验收绿灯且上线批准后的发布流程。任何一步不达标就停（前置检查 = 硬门），不绕过。

## 前置检查（全过才继续）

- [ ] 票上有验收绿灯报告 + 上线批准卡已通过
- [ ] 目标分支与票一致，含最新提交
- [ ] 回滚方案明确（如何回退、谁验证）

## 发布步骤

1. 按仓库/环境既定发布流程执行（沙箱/CI 回调/运维脚本）。
2. 发布后跑健康检查与冒烟（标量命令，不看日志正文全文）。
3. 把部署链接/日志摘要与健康检查结果贴到票评论。

## 失败处理

- 健康检查不过 → 按回滚方案回滚，票转 `blocked`；记录回滚证据与原因，请人类决策。
- 不回滚直接重试 = 禁止。

## 留痕

- 每次发布记录：版本/提交、环境、时间、结果、证据链接。
- 不把任何生产密钥/内部地址贴进票或聊天。
