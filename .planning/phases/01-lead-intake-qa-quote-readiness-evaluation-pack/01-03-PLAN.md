# Plan 03 — Hermetic Campaign Runner, Evidence, and Independent Verifier

## Objective

Build the two-process evaluation system: a restricted campaign runner that produces evidence and an independent deterministic verifier that owns expected outcomes and the final verdict.

## Tasks

### 1. Build the campaign runner

Implement a CLI that accepts pack/campaign IDs, runtime mode, iteration count, output directory, and candidate revision. Default to scripted runtime + fake sandbox. Refuse live Pi unless the evaluation policy preflight passes and the computer is dedicated.

Run cases in stable order, three iterations each. Stop the campaign after a shutdown trigger; do not silently skip cases.

**Verify:** Dry-run lists exactly 60 planned runs. Resume requires a valid sealed checkpoint and cannot duplicate a completed run.

### 2. Produce canonical evidence

Create per-run packets and a campaign manifest per `01-EVALUATION-PACK.md`. Use canonical JSON and Node crypto SHA-256. Record state transitions, policy denials, usage, retries, timestamps, revision, uncertainties, and terminal reasons.

Never store raw synthetic credential/sensitive canaries beyond boolean/category detection.

**Verify:** Packet/manifest schemas and hashes validate; tampering any byte invalidates the manifest.

### 3. Implement the independent verifier

The verifier runs as a separate CLI/process. It receives read-only evidence and expected roots. It does not import the model runtime, connector stack, sandbox, or executor. Calculate exact issue/class/queue agreement, critical gates, policy safety, evidence completeness, reproducibility, timing, retry, budget, shutdown, and rollback metrics.

Return:

- 0 + `ACCEPT`
- 1 + `REJECT`
- 2 + `INVALID_PACK`

Include stable reason codes and a machine-readable report.

**Verify:** Dependency/architecture tests prove the verifier cannot import or call AI/runtime/connectors.

### 4. Mutation-test the verdict

Create generated test mutations for unauthorized action, false quote-ready, unsupported claim, wrong queue/class, missing critical issue, missing packet, corrupt hash, exceeded budget without halt, excessive retry, unstable outcome, failed shutdown, and failed rollback.

**Verify:** Every mutation independently produces exit 1 or 2 as specified; the pristine golden campaign exits 0.

### 5. Add explicit package scripts

Add scripts with clear names, for example:

```json
{
  "test:eval:lead-intake-v1": "tsx packages/testkit/src/cli/lead-intake-eval.ts",
  "verify:eval:lead-intake-v1": "tsx packages/testkit/src/cli/lead-intake-verify.ts"
}
```

Do not overload `pnpm test` with live-model work. Offline corpus/verifier tests remain part of normal tests; the 60-run campaign is explicit.

## Plan Verification

```bash
pnpm test -- packages/testkit/src/evaluations/lead-intake-v1
pnpm test:eval:lead-intake-v1 -- --runtime=scripted --sandbox=fake --iterations=3 --output=test-report/lead-intake-quote-readiness-v1/golden
pnpm verify:eval:lead-intake-v1 -- --campaign=test-report/lead-intake-quote-readiness-v1/golden
```

## Exit Gate

- Golden scripted/fake campaign produces 60 packets and exits ACCEPT.
- Every mutation is rejected/invalidated.
- Verifier process has no AI/runtime/connector dependency.
- No live model, connector, browser, or external system was used in this plan's automated verification.
