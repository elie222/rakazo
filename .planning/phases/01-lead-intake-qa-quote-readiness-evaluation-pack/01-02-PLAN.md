# Plan 02 — Task-Scoped Policy, Budgets, Approval Binding, and Shutdown

## Objective

Add a default-deny evaluation execution envelope around the existing executor without weakening ordinary Rakazo behavior. The feature is additive, disabled by default, and scoped to evaluation runs only.

## Repository Grounding

- `packages/adapters/src/executor.ts` currently records non-read-only effects and then dispatches broad built-in and connector tools.
- `packages/adapters/src/builtin-tools.ts` defines bot lifecycle, computer, shell, and takeover tools.
- `ExternalEffect` provides idempotency but is not a policy decision record.
- `packages/testkit/src/executor-lifecycle.test.ts` already tests fail-closed uncertain effects.

## Tasks

### 1. Introduce an explicit evaluation policy contract

Create an additive `RunPolicy` persistence record bound one-to-one to a Run with `kind`, `pack_id`, `campaign_id`, `case_id`, run/user/workspace, allowed tool IDs, evidence root, budgets, expiry/revocation, and policy hash. The worker loads it before model execution. Evaluation mode must require this record; absence or mismatch fails preflight. Keep `EVAL_PACK_V1_ENABLED=false` in `.env.example` and default behavior.

Do not reuse a bot prompt or free-form instructions as the policy source.

**Verify:** Wrong workspace, user, run, case, expiry, hash, or feature flag denies the run before model execution.

### 2. Filter model-visible tools and gate dispatch

Apply the policy twice:

1. Construct the model tool list from the allowlist only.
2. Recheck normalized tool identity immediately before `applyTool` side effects.

Expose only dedicated `evaluation_read_case`, `evaluation_write_result`, `evaluation_halt`, and `evaluation_request_review` tools. Recheck that `evaluation_write_result` targets the current run's evidence location. Normalize aliases such as `destination_write`/`destination.write` only to deny them consistently. Unknown tools deny by default. Emit a policy-denial event with arguments redacted and no completed external effect.

**Verify:** Table-driven negative tests attempt every built-in and connector category, aliases, unknown names, direct dispatch, and duplicate execution IDs. No prohibited handler is invoked.

### 3. Enforce budgets outside model control

Track turns, allowed tool calls, wall clock, input/output tokens, integer microdollar estimated cost, and retries. Enforce limits at exact boundaries in worker/executor control code, not prompts. Serialize campaign/run accounting with the existing fenced-lease pattern.

On breach, cancel the run, set `HALTED_BUDGET`, revoke the policy, seal partial evidence, and prevent automatic retry beyond one.

**Verify:** Boundary tests pass at the exact ceiling and halt at ceiling + 1 for every dimension.

### 4. Bind approvals without widening authority

Define approval receipts in the append-only campaign evidence stream with actor, action type, artifact/policy hash, issued/expiry times, and nonce. Only the four gates in the pack may consume them. A manual case override records disagreement but cannot change the deterministic campaign verdict to ACCEPT. Evaluation tool denials reuse the existing Event stream and are sealed into the hashed campaign manifest; they do not require a second effect table.

**Verify:** Replay, expiry, wrong actor/action/hash/campaign, and mutation after approval all fail.

### 5. Implement shutdown and rollback hooks

Add an evaluation campaign control capable of stopping new work, cancelling the active run, disabling evaluation jobs, revoking policies, and stopping/suspending the dedicated computer. Seal a shutdown receipt within 60 seconds.

Guard the entire surface behind `EVAL_PACK_V1_ENABLED=false` by default. Do not create an active routine as part of this phase.

**Verify:** Inject policy breach, budget breach, operator kill, runtime loss, and evidence corruption. Assert no later action/case starts and ordinary bots remain unchanged.
